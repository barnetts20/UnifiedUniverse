# Review tonight — Unified Universe prototype, day 1

## 1. Summary
The engine-agnostic core is built and verified offline through Tier 3: the 128-bit coordinate, seeds, level windows, the generation pipeline (cosmic web → galaxies → stars), and the project-and-cull renderer. Every check in `Verification/REPORT.md` is green. The Unreal side (four modules, GPU generation and backdrop passes, view extension, subsystem, console commands, Automation tests) is written but **has never been compiled**. There was no engine here, folder access to your laptop was declined, and DXC could not be run. Several design questions were settled by measurement, and two of the answers change the design, so **look first at §4: D-118 (level assignment needs N − 1/K for no-pop streaming) and D-107/D-109 (seeds)**. Then build (§3, step 1).

## 2. Verified
All offline, in `Verification/REPORT.md` (generated by `Tools/UniVerify/verify_all.py`). Images are in `Verification/images/`, and what I saw in them is in `Verification/OBSERVATIONS.md`.

- **Coordinates (Tier 1).** 10^6 fuzz cases, zero mismatches across `UniCoord.h`, `UniCoord.ush` (run on the CPU through the shim), `__int128` and a Python big-int oracle. The oracle was mutation-tested: 9 of 9 planted corruptions caught. ToHiLo worst error is 2^-49 (limit 2^-46). Borrow chains, root wrap, antipode, extreme `AddDisplacement` and hex round trip all pass. g++, clang, and a strict C++20 `-Wshadow` build are all clean.
- **Seeds.** Chi-squared inside the 99% band for sequential inputs on every seed path. ProcSeed's recorded lesson is reproduced: without Avalanche, chi-squared is 1.26e7. Object seeds have zero collisions over 300 cells × 2^15 (D-109). A Python oracle agrees on 2,007 cases.
- **Windows and levels.** Zero slot-bijection, stability or diff violations over 5,184 slides at N = 1..6, including the root seam (D-100). Level coverage: zero violations in 240k trials. f(r) and photometry are within their float bounds (D-110).
- **Generation (Tier 2), on two scenes (cosmic web → galaxies; galaxy → stars).** Determinism: 54,864 cells, 0 differ across histories and evict-and-revisit. Counts: z = −0.88 over 12,735 tasks. Slicing conserves N_total to 0.2%. Fidelity: r = 0.92 (galaxy disc) and 0.98 (web). Coverage: 416k children, 0 outside their contributor. Slice draws: 24 slices, 0 outside. The budget is under the D-005 caps. The baked UniVol path (format, mips as exact means, mip-descent placement r = 0.999, 48 tile symmetries) also passes.
- **Runtime streamer.** The asynchronous probe → allocate → place protocol, with a CPU backend, reproduces the reference pipeline cell for cell: 5,375 cells and 719,687 objects identical (T2.stream.parity).
- **Rendering (Tier 3).** Jitter: worst 2.6e-3 px with the camera parked at 1e30, 1e35 and 2^127 cm and stepped 0.001 cm per frame (limit 0.01). The design's hi/lo form is 1.6e4 px off for near objects in coarse cells, which is why D-104 changed it. Ordering: 0 reversals in 100k pairs (per-depth compression gets 2,284 wrong). Occlusion: 0 wrong in 20k placements. Flythrough from 3 Gpc to 1 m above a star: **0 pops** among 545,902 entering objects, after fixing three real pop sources it found (D-116, D-117, D-118).
- **Static UE checks.** Shader cores stay in the shared subset. Every GPU struct is asserted to a multiple of 16. Render hooks are in one file. No UE includes in UniCore.

2. **Automation tests (UE-2).** Run `"<UE>\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" "D:\Projects\vxl\vxl.uproject" -ExecCmds="Automation RunTests UnifiedUniverse;Quit" -unattended -nullrhi -nosplash -log`.

   - Failure looks like: `SeedEngineParity` fails with "Set UNI_SEED_HASHCOMBINE_FAST to N". Do that in `Shaders/Private/Core/UniSeed.ush` (D-107). Only rolled archetype parameters change; content identity does not (D-109).

3. **Shaders (UE-3).** Start the editor. Global shaders compile at startup.
   - Expect: no shader errors in the Output Log for `FUniGenProbeCS`, `FUniGenPlaceCS`, `FUniScatterCS`, `FUniProjectCS`, `FUniSpriteVS` or `FUniSpritePS`.
   - Failure looks like: "Failed to compile global shader …". Set `r.ShaderDevelopmentMode=1` in ConsoleVariables.ini to get the error text. Likeliest causes: relative `#include "Core/…"` resolution, and `StructuredBuffer` passed as a function parameter in `UniPlacement.ush` / `UniGenTask.ush`. If `FUniGenPlaceCS` fails with X4026 ("thread sync operation must be in non-varying flow control", FXC/SM5 only), delete the marked `if (GsBase >= Capacity) { break; }` line in `UniGen.usf`; results do not change.

**Moving around (test controls).** The default pawn tops out around 12 m/s, which is useless at these scales. Use free flight:
- `uu.Fly` toggles it. Steer with the mouse, move with W/S (forward/back), A/D (strafe), E/Q (up/down).
- The mouse wheel doubles or halves the speed. `uu.Speed <cm/s>` sets it directly at any magnitude: `3e5` = 3 km/s, `3e10` ≈ c, `3e21` ≈ 1 kpc/s.
- A cyan HUD line shows the speed in natural units (for example "1.2 kpc/s") and your distance from the demo origin (the galaxy's centre).
- `uu.Fly` again returns to Local mode without a jump.
- `uu.Cruise <cm/s>` now holds a straight-line velocity at any speed until you set it to 0. Before, anything under 1e8 cm/s was silently ignored by the D-008 threshold.
- Velocity LOD reacts to whatever speed you choose: at extreme speeds the finer levels suspend (and, on the volume branch, show as glow).

4. **See it (UE-5).** Create a new Empty Level with no sky or atmosphere, so stars are not drowned, and press Play. In the console run `uu.Enable galaxy`.
   - Expect: within about a second (levels fill coarse to fine, about 37 frames), a band of stars across the sky, as in `Verification/images/still_galaxy_towards_centre.png`. Look along −X for the galactic centre. Then run `uu.Stats`: cells ready > 2,000, `gpu done` > 0, `failed` 0, and "cells drawn" > 0.
   - Failure looks like: black. Read `uu.Stats`. If cells are ready but nothing is drawn, it's the sprite pass or the hook; capture a frame in RenderDoc and look for the "UnifiedUniverse" event scope. If batches failed (timeouts), the generation passes are not running. Brightness is uncalibrated (lesson #36), although the sprites now follow the view's pre-exposure: try `uu.Exposure -3` (brighter) or `+3`, and disable auto-exposure if the empty level blows it out.

5. **Occlusion (UE-5).** Place a large sphere mesh in front of the camera.
   - Expect: stars behind it are hidden, and stars around its silhouette are crisp.
   - Failure looks like: stars drawn over the mesh. That points to the depth-UV mapping after TSR (`DepthUVScaleBias` in `UniRenderer.cpp`); first try with `r.ScreenPercentage 100`.

6. **Flythrough (UE-6).** Run `uu.Flythrough 60`.
   - Expect: a 60 s dive from 3 Gpc to 1 m above a supergiant of the anchored galaxy, as on `Verification/images/flythrough_contact_sheet.png`. The first ~25% is near-black, which is designed (velocity LOD at extreme speed). Then stars fade in level by level with no pops or jitter, and the target star grows.
   - Failure looks like: stars appearing at full brightness (pops), shimmering (TSR before the hook, or jitter), or long black gaps after the camera slows (generation latency, UE-8).

7. **Promotion glare (UE-7).** At the end of the flythrough, judge how the target's sprite glare reads with real bloom. There is no promotion actor pool yet, so it never becomes a mesh.

8. **Cost (UE-8).** Run `stat gpu` and `profilegpu` during the flythrough and note `Uni.Gen.*`, `Uni.ProjectAndCull` and `Uni.Sprites`. Expect a one-time hitch of about 0.2 s when the camera first enters the galaxy (D-123).

9. **GPU parity (UE-4).** Run `uu.Disable`, then the Automation test `UnifiedUniverse.Render.GpuParity`, **without** `-nullrhi`.
   - What it does: generates the solar-camera scene on the GPU and on the CPU side by side, and compares every ready cell object by object.
   - Expect: counts equal in ≥ 99% of cells, and integer parts identical in ≥ 99% of objects. Its info line gives the exact rates (D-105).
   - Failure looks like: counts off everywhere (probe pass or slice tables), or counts right but offsets wrong (the place pass's scan). BUILD_TRIAGE §4 has more.

## 4. Needs your decision
- **D-118 (HIGH reroll): level assignment uses N_eff = N − 1/K = 1.75, not N = 2.** The design's claim that objects stream in where they are already invisible does not hold with N = 2: the window lags the camera by one frame, and the flythrough measured pops. With 1.75 there are 0 pops. Cost: about 1.5× residency. The alternative is to keep N = 2 and accept fade-band pops. Decide before any content is authored.
- **D-107 / D-109 (HIGH): seeds.** ProcSeed's recorded statistics match the *fast* `HashCombine` form, not the Jenkins mix, so the port defaults to that. UE-2 decides. Separately, the design's object seed `MixSeed(CellSeed, index)` collided 5–260× above the birthday rate, so cell and object seeds use an injective mixer instead (D-109). That defines all generated content.
- **D-104: exact 128-bit per-cell deltas** replace the design's hi/lo floats for project-and-cull (measured: hi/lo is 1.6e4 px off near bright stars). This is render-only, but it is a design change.
- **Still open from kickoff:** D-002 (coordinate width), D-010 (N), D-011 (m_ref, θ_min), D-008 (motion modes; your design-doc comment is still unanswered).
- **Laptop access:** nothing was written outside the cloud workspace; installing is §3 step 0.

## 6. Known issues and blocked items
- **Nothing UE-facing has been compiled**: there was no engine and no engine headers here. An independent reviewer, who had not seen the code being written, read all of it against UE 5.3–5.6 conventions. Its list of the five likeliest failures tonight was B1, W1, R1, S1 and B2/R4. All of them are now fixed in code, but none of the fixes has been compiled. Recorded as D-127.

  | ID | Finding | Fix |
  | --- | --- | --- |
  | B1 | `UniSubsystem.h` forward-declared types held in `TUniquePtr`; the UHT-generated destructor cannot delete them | Includes `UniStreamer.h` before `.generated.h` |
  | B2 | `FRHIGPUBufferReadback` and friends need `RHICore` | Added to the Render module's dependencies |
  | B4 | `ShadowVariableWarningLevel` moved to `CppCompileWarningSettings` in 5.5 | All four Build.cs files guarded with `#if UE_5_5_OR_LATER` |
  | B5 | `TStaticBlendState` used without `RHIStaticStates.h` | Included |
  | R1 | Sprites were drawn straight into the post-process input, which need not be render-targetable | Copy into `OverrideOutput` or a new target, then draw into that |
  | R2/W5 | A failed batch could leave pool slots unwritten but drawn; the read offset was shared across cells | `bFailed` handled in both phases, per-cell read offset; new check `T2.stream.fail_closed` (749 cells failed closed, 0 unwritten slots drawn) |
  | R3 | Probe and place shared one set of request flags, so a late probe command could mark the place phase submitted | Separate per-phase flags; the timeout starts when the render thread runs the command; timeouts fail closed |
  | R4 | The renderer's pooled buffers outlived the RHI at exit | Released on `OnEnginePreExit` with a render-thread flush |
  | W1 | Cleared sky (reverse-Z depth 0) produced a NaN or negative distance, which would hide every star | Depth 0 is treated as infinitely far |
  | W2 | The jittered projection was used after TSR, so stars would wobble by the TAA jitter | Unjittered (`ComputeProjectionNoAAMatrix`) projection and field of view |
  | W3 | Scene colour is pre-exposed at this point; the sprites were not | Sprite radiance is multiplied by `PreExposure` |
  | W4 | Local-mode anchor re-entry and teleport ignored the pawn's view location; the flythrough left a velocity behind | Anchor = camera − view location; velocity zeroed at the end |
  | W6 | Scene captures and editor views also got the backdrop | Game views only, with `OverrideOutput` still honoured |
  | S1 | `UniGen.usf` returned early before group barriers and had an unbounded loop | No early return (padding groups do zero work and mask their writes); the place loop is bounded by the candidate budget |

  **Remaining risks from that review:** S1's early-out `break` may still trip FXC on SM5 (fallback in §3 step 3). `FViewInfo` (used for the internal view rect and `PreExposure`) needs the Renderer's private include path, which may change between engine versions. Reviewer item R5 (the promotion readback ring is never drained on teleport) is harmless for now, because promotion has no consumer yet. W7 (a cosmetic log-spam item) was not changed.
- **DXC was not runnable** (session policy refused executing the downloaded binary; not worked around). Shader syntax is unverified (UE-3). The shader *logic* is verified by running the same cores on the CPU.
- **UltraLargeScale reference** is the GitHub snapshot `cb2ccc5` (2026-08-30). Your laptop copy may be newer. `ULSScaleLadder.h` is not in that snapshot, so `UniScaleLadder.h` is a fresh implementation.
- **Coarse cells miscount** by 3–18% where a contributor spans ≤ 8 cells per axis (the bright end of the star luminosity function). The fix is adaptive probing (D-103).
- **Teleport fill takes about 37 frames** (two GPU round trips per level, serialised over ~18 levels, D-122).
- **Normalising integral hitch**, about 0.2 s, when first entering a galaxy (D-123).
- **The cosmic web is not visually legible** in the reference still (65 galaxies at Δm = +5). Web placement is verified numerically, not visually.
- **Not built today:** promotion actor pool and local-anchor re-centring (M3), resolve/query/pick/events/persistence API, volumetrics, sensitivity ping and cone, the UniVol editor importer, the A/B comparison map. Test content (`.umap`) cannot be authored without the editor, so §3 uses an empty level plus console commands.
- **Stretch P6 not reached.**
